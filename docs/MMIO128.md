## 总线契约

所有接口工作在同一个 `clk` 域，`rst` 为同步高有效复位。
本地总线使用 16 bit **字节地址**、32 bit 数据、4 bit 字节写选通：

| 通道 | 信号 | 语义 |
| --- | --- | --- |
| 请求 | `req_valid/ready` | 上升沿二者均高才接受，写/地址/数据/选通随请求保持 |
| 请求内容 | `req_write/addr/wdata/wstrb` | 读为 0、写为 1；地址必须 4 字节对齐；字节 0 对应低 8 bit |
| 响应 | `rsp_valid/ready` | 每个被接受的请求产生一个寄存的响应；读写都要收取响应 |
| 响应内容 | `rsp_rdata/error` | 写响应及错误读响应的数据为 0；错误请求不产生目标副作用 |

最多保留一个未消费响应；响应受阻时内容不变且停止接受请求。
消费旧响应的同一拍可以接受新请求，支持连续每拍一笔。
读响应是请求握手时的快照，后续计数器或状态变化不会改变已产生的响应。
对忙设备的非法操作立即返回错误，不把请求无限挂起等待空闲。
外部复位在时钟沿取消未消费响应，并丢弃运行中的任务和未读输出。

这是独立本地协议，**尚未实现 AXI/AXI-Lite、UART、CPU、DMA 或 CDC**。
后续桥接器须把系统地址译成该局部偏移，并保留写选通及错误响应，不能截断越界系统地址后产生别名。
目前设备规格固定为 16×16、Ci≤768、Co≤16，两个激活 bank 各 24,576 个 64 bit 字，权重 864 个 1024 bit 字。

## ABI 1.0 寄存器

除下表外的地址均报 `ADDRESS` 错误，不会镜像到低地址。
RW 暂存寄存器按实际 WSTRB 合并字节；零选通对合法可写地址不产生操作。
RO 写入报错。动作寄存器读回 0；动作值先经 WSTRB 掩码，保留位非零报 `RANGE`。

| 字节偏移（十六进制） | 名称 | 属性及内容 |
| --- | --- | --- |
| `000` | ID | RO，`0x4e505531`（NPU1） |
| `004` | ABI | RO，`0x00010000`（major 1、minor 0） |
| `008` | CONTROL | WO 动作：1=START、2=SOFT_RESET；0 无操作，两个动作不能合写 |
| `00c` | STATUS | RO 状态；仅 bit2 DONE 支持写 1 清除 |
| `010` | ERRORS | 五位 sticky 错误，按选通写 1 清除；新错误优先于同拍清除 |
| `014` | ACT_WORDS | RO，每 bank 24,576 |
| `018` | WEIGHT_WORDS | RO，864 |
| `01c` | OUTPUT_COUNT | RO，本次已捕获的输出向量数，不是已弹出数 |
| `020` | SHAPE | RW，width[7:0]、height[15:8]、Cin[31:16] |
| `024` | OPTIONS | RW，Co[4:0]、kernel3[5]、stride2[6]、pad[7]、mode[9:8]、bank[10]；其余为 0 |
| `028` | ACT_INDEX | RW，bank[31]、64 bit 字索引[30:0]；合法索引 0–24575 |
| `02c` | WEIGHT_INDEX | RW，1024 bit 字索引；合法索引 0–863 |
| `030` | CFG_INDEX | RW，通道或表地址[7:0]、kind[9:8]；提交时其余位必须为 0 |
| `034` | CFG_DATA | RW，待提交的配置数据 |
| `038` | ACT_COMMIT | WO，写 1 提交当前索引及 64 bit 激活暂存字 |
| `03c` | WEIGHT_COMMIT | WO，写 1 提交当前索引及 1024 bit 权重暂存字 |
| `040` | CFG_COMMIT | WO，写 1 提交 kind/address/data |
| `044` | OUTPUT_POP | WO，写 1 弹出当前输出；空槽时报 STATE |
| `048/04c/050/054` | PERF_MAC/CONV/TOTAL/POST | RO，核心的 MAC 发射、卷积活动、命令总周期、后处理等待计数 |
| `058` | OUTPUT_META | RO，mask[15:0]、x[23:16]、y[31:24]；空槽时报 STATE |
| `05c` | OUTPUT_FLAGS | RO，mode[1:0]、last[2]、valid[3]；空槽返回 0 |
| `060/064` | ACT_DATA | RW，激活暂存字的低/高 32 bit |
| `080–0bc` | BIAS[0–15] | RW，每通道一个 INT32，地址步长 4 |
| `100–17c` | WEIGHT_DATA[0–31] | RW，1024 bit 暂存字，地址步长 4；低地址对应低位 |
| `200–23c` | OUTPUT_RAW[0–15] | RO，每通道一个 INT32；空槽时报 STATE |
| `240–24c` | OUTPUT_INT8[0–3] | RO，每字四通道，通道 0 在最低字节；空槽时报 STATE |

STATUS：bit0 BUSY、bit1 OUTPUT_VALID、bit2 DONE、bit3 ERROR、bit4 LUT_READY。
DONE 和 ERROR 是 sticky；核心最后输出进入读回槽后报告 DONE。
因此 DONE 可以与 OUTPUT_VALID 同时存在，表示最后一个向量还需要软件读取、弹出。
新的 START 清除 DONE 和 OUTPUT_COUNT；未弹出的结果会阻止 START，即使 BUSY 已为 0。
BUSY 包含命令启动和错误收尾状态；轮询驱动应分别处理 OUTPUT_VALID、ERROR 和 DONE/BUSY。

ERRORS 位定义：bit0 ADDRESS（地址、对齐、RO 写）、bit1 STATE（忙时禁止的提交、空读/空弹出、未读输出时启动）、
bit2 RANGE（索引越界、动作/选项保留位）、bit3 COMMAND（核心描述符/模式错误）、bit4 CONFIG（核心配置错误）。
前三类同时产生 `rsp_error`；后两类是核心接受操作后产生的设备错误，
对应动作的总线响应成功只表示操作已下发。读 ERRORS 可观察新到达的核心错误，无须等待下一次状态寄存。

## 装载、运行和结果所有权

数据窗口是**暂存区**，不是对核心 SRAM 的直接读写映射：

1. 写索引、完整数据暂存字，再写 COMMIT=1；只有 COMMIT 握手才修改核心 RAM。
2. 激活一个字 8 个 INT8；权重一个字为 16 输出通道×8 输入通道，通道与 tap 顺序沿用 ADAM128。
   字节 0 对应 oc0/ic0，字节 8 对应 oc1/ic0；尾输入、尾输出通道按原核心掩码处理。
3. 不自动递增索引，也不把某个字节写当作 SRAM 的读改写。软件需装好所有将被读取的数据。
4. 允许忙时修改下一任务的描述符、bias 和数据暂存区；当前任务使用 START 时锁存的参数。
   忙时仅允许向**非活动激活 bank**提交，权重及配置 COMMIT 被拒绝。
   修改 OPTIONS.bank 不改变当前运行任务的 bank 保护。
5. 配置 kind=0/1/2 分别为逐通道乘数、右移量、顺序 256 项 LUT，数值规则沿用 NPU.md。
   LUT 未完整装载不能使用 mode2。非法配置不替换有效配置。

每次输出捕获整个 16 通道向量，包含 RAW、INT8、mask、坐标、mode、last。
软件可以分多次读完这些寄存器，期间输出保持不变；显式 POP 才释放槽位。
POP 与下一向量捕获可同拍发生，旧读响应保留旧向量快照。
满槽自动向核心施加背压，不覆盖未读结果，也没有额外整块输出 RAM。
多像素任务必须边运行边弹出，不能先等待整个任务 DONE 再开始读输出。

软件操作顺序为：检查 ID/ABI → 清旧错误 → 配置系数/LUT → 装输入和权重 →
写描述符/bias → START → 轮询并读取/弹出所有向量 → 确认 DONE、BUSY=0、无错误。
应用可在当前任务进行时预装另一 bank，当前输出全部读走后再启动下一任务。
索引、暂存、提交与读回/弹出序列须由**一个软件所有者**串行管理，不支持多个主机同时修改暂存区。

SOFT_RESET 可在任意工作状态执行：清运行、输出、暂存区、计数器、错误和后处理配置有效状态，
但保留该 RESET 请求的总线响应。默认描述符为 1×1/Ci8/Co16、raw、bank0，乘数 1、shift 0、LUT 未就绪。
外部复位还取消未消费的总线响应。
两种复位均不清除激活、权重或 LUT RAM 内容；有效性状态复位，首次使用前仍必须正确装载。
未实现 RAM 已装载字覆盖跟踪、设备超时或总线之外的错误中断。

## 软件入口与验证

`software/npu128_mmio.h` 只依赖 C11 的 `stdint.h`，包含寄存器常量、描述符打包、
激活/权重提交、配置提交及完整输出读取/弹出辅助函数。
`npu128_io` 通过 `read32/write32` 回调连接实际传输；回调必须等到读/写响应并返回错误。
平台 MMIO 的 volatile、fence、缓存维护和串口协议属于后续适配，不由此头文件代替。
形状打包调用方须提供合法字段位宽；支持的卷积形状由核心在 START 时检查。

`npu128_read_output` 返回 1 表示取走一个向量、0 表示暂无输出、负数表示传输错误。
数据读取失败时不 POP，可以重试；测试已注入中途读失败核对该行为。
`npu128_configure` 提交后读取 sticky ERRORS，使用前需先清除旧错误。

```bash
make mmio-lint
make mmio-test
# 保存新报告时使用未占用的路径；不覆盖历史证据。
python3 tools/run_mmio_tests.py --build-dir build/mmio-new \
  --output build/mmio-new/validation.json
```

[功能验收报告](../reports/npu128-mmio-validation.json) 绑定测试源码、实际命令、可执行文件和原核心物理参照的 SHA256。
最终公开端口测试结果为：

测试使用固定随机种子的合成整数张量和非模型激活表，不是完整 YOLOX 推理。

- 19 个有效任务，672 个向量、10,752 个通道槽，RAW 和三种模式的 INT8 输出均与独立标量参考比较。
- 269,859 次总线事务、404,665 拍响应背压；另有连续请求/响应、随机字节选通和响应顺序核对。
- 两个激活 bank 的全容量、8192/16384 段边界、最高字 24575，以及全部 864 个权重字。
- 1×1/3×3、stride/padding、Ci/Co 尾通道、INT32 回绕、LUT[0] 非零下的尾通道清零。
- 活动 bank 毒化写、忙时权重/配置毒化提交及重复 START 被拒绝；非活动 bank 预装载和切换正常。
- 输出长时间保持、同拍弹出/补入、最终未读输出阻止新启动；非法地址、索引、配置及描述符恢复。
- soft/hard 两次运行中止恢复；硬复位取消被阻塞的读响应，软件复位响应保留；新错误优先于同拍 W1C。
- C ABI 通过主机编译器严格 C11 检查；不等于已有 RISC-V BSP 或板端运行证明。

首轮测试以固定 250 拍等待首输出，在 Ci768/3×3 单像素上过早失败；
改为有界轮询等首输出后再施加停顿。失败构建 `build/mmio`、初次通过 `build/mmio-r2` 及最终加强版 `build/mmio-final` 均保留。
最终编译约 9.07 秒、采样峰值 RSS 375.4 MiB，仿真约 0.77 秒、4.2 MiB；单线程，
进程组 RSS/地址空间上限 768/1536 MiB，Linux 可用内存至少保留 6 GiB。
原计算核哈希与已验收 RAM 版本一致，51 个第三方文件字节不变。

## 本阶段结论与下一步

本阶段只完成最小设备的功能闭环，未改动 hgb，也未生成位流。
单向量读回槽会使计算等待软件读数，新的 TOTAL/POST 包含这种停顿，
不能把原 always-ready 分块周期直接当作该 MMIO 驱动的总延迟。
未对新包装顶层运行 PDS，**不能把原计算核的 100 MHz 收敛结论扩展为外围或 SoC 的时序结论**。

接续先选择板级串口桥或实际系统总线适配，核对板卡时钟、同步复位与引脚约束，
再对完整顶层执行综合、布局布线和单卷积上板；DDR/DMA、跨域和完整模型随后分别验收。
